1. INTRODUCTION: TAILWIND CSS UTILITY-FIRST PHILOSOPHY
--------------------------------------------------------------------------------
Traditional CSS requires developers to invent arbitrary class names and switch
back and forth between markup and separate stylesheet files:
  .project-header-container-v2 {
    display: flex;
    justify-content: space-between;
    padding: 16px;
  }

Problems in Enterprise Frontends:
  - Naming fatigue: Spending hours deciding names like "wrapper-inner-left".
  - Dead CSS buildup: Unused CSS files grow indefinitely out of fear of breaking UI.
  - Inconsistent spacing: Developers mixing 13px, 14px, 15px, 18px arbitrarily.

Tailwind CSS solves this using a Utility-First Design System:
  - Predefined constraints: Standard spacing scales (p-2 = 0.5rem, p-4 = 1rem).
  - Co-located styling: Markup and styles live together directly in JSX.
  - Zero unused CSS: Tailwind purges unused utilities at build time.


2. RESPONSIVE DESIGN & MOBILE-FIRST BREAKPOINTS
--------------------------------------------------------------------------------
Tailwind enforces a mobile-first philosophy:
Unprefixed utilities apply to ALL screen sizes (starting from 0px).
Prefixes only trigger when viewport width exceeds the specified breakpoint:

  Breakpoint   Minimum Width   Target Devices
  ----------   -------------   -----------------------------
  sm:          640px           Large phones, small landscape
  md:          768px           Tablets, iPads
  lg:          1024px          Laptops, desktop displays
  xl:          1280px          Large desktop monitors

Example: Responsive Card Layout
  <div className="flex flex-col sm:flex-row items-start sm:items-center justify-between p-4 sm:p-6">
    <!-- Stacks vertically on mobile; aligns horizontally on tablets and above -->
  </div>


3. WHAT IS SHADCN/UI? (AND HOW IT DIFFERS FROM COMPONENT LIBRARIES)
--------------------------------------------------------------------------------
Most UI libraries (MUI, Ant Design, Chakra UI) install as locked node_modules packages:
  - Hard to customize without complex theme overrides.
  - Heavy bundle size overhead (imports components you don't even use).
  - You do not own the code.

shadcn/ui is NOT a component library — it is a collection of re-usable components
that you copy directly into your project's codebase:
  1. You own the code: Components live in `components/ui/button.tsx`.
  2. Built on Radix UI: Headless accessible primitives (WCAG AA compliant, keyboard accessible).
  3. Styled with Tailwind CSS: Effortless customization by simply changing class names.
  4. Zero bloat: Only add the components your application actually needs.


4. THE `cn()` UTILITY FUNCTION
--------------------------------------------------------------------------------
shadcn/ui uses the `cn()` helper to merge Tailwind classes safely:

  import { clsx, type ClassValue } from 'clsx';
  import { twMerge } from 'tailwind-merge';

  export function cn(...inputs: ClassValue[]) {
    return twMerge(clsx(inputs));
  }

Why both `clsx` and `tailwind-merge` are needed:
  - `clsx`: Conditionally toggles classes (e.g. isActive && 'bg-blue-500').
  - `tailwind-merge`: Resolves conflicting Tailwind utilities cleanly.
    Example: `cn('p-4 text-red-500', 'p-6')` -> resolves cleanly to `'text-red-500 p-6'`.
    Without `tailwind-merge`, both `p-4` and `p-6` would be emitted in the class list.


5. SONNER: ENTERPRISE TOAST NOTIFICATIONS
--------------------------------------------------------------------------------
NirmanIQ uses Sonner for toast alerts across all construction monitoring dashboards:
  - Lightweight and highly performant.
  - Accessible: Uses ARIA live regions to notify screen readers.
  - Rich colors: Distinct visual styling for success, error, warning, and info.

Setup in Layout:
  import { Toaster } from 'sonner';

  export default function RootLayout({ children }) {
    return (
      <html>
        <body>
          {children}
          <Toaster position="top-right" richColors />
        </body>
      </html>
    );
  }

Triggering Toasts in Components:
  import { toast } from 'sonner';

  toast.success('Project created successfully!');
  toast.error('Failed to save project. Please check form inputs.');
