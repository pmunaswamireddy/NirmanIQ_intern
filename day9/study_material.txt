1. THE MENTAL MODEL: WHY UTILITY-FIRST CSS?
================================================================================
Traditional CSS workflow requires creating separate CSS files and naming classes:
```css
/* Traditional CSS approach */
.project-card-header-v2 {
  display: flex;
  justify-content: space-between;
  padding: 16px;
  background-color: #ffffff;
}
```

Problems Encountered in Real-World Teams:
1. **Naming Fatigue**: Spending valuable development time inventing class names like
   `container-wrapper-inner-left`.
2. **Stylesheet Bloat**: Over time, CSS files grow into megabytes because developers
   are afraid to delete old styles for fear of breaking unrelated pages.
3. **Inconsistent Design**: One developer uses `margin: 15px`, another uses `margin: 18px`,
   leading to an unpolished, misaligned UI.

How Tailwind CSS Solves This:
Tailwind provides small, composable utility classes directly in your HTML/JSX:
```tsx
<div className="flex justify-between p-4 bg-white rounded-lg shadow-sm">
  ...
</div>
```

Key Advantages:
- **Design Tokens Out-of-the-Box**: Consistent spacing scale (p-2 = 8px, p-4 = 16px, p-6 = 24px).
- **Zero Dead Code**: Tailwind analyzes your source files and generates CSS ONLY for
  the classes you actually use.
- **Speed**: Style components directly inside your JSX without switching files.

2. MOBILE-FIRST RESPONSIVE BREAKPOINTS & LAYOUT PATTERNS
================================================================================
In Tailwind, styling is **Mobile-First** by default.

Rule:
- An unprefixed utility applies to EVERY screen size from 0px upwards.
- Breakpoint prefixes (like `md:`) only activate when the screen is AT LEAST that wide.

Standard Breakpoints:
--------------------------------------------------------------------------------
Prefix    Min Width    Typical Target Devices
--------  -----------  ---------------------------------------------------------
(none)    0px          Mobile devices in portrait mode (default)
sm:       640px        Large phones, small tablets
md:       768px        Tablets, iPads
lg:       1024px       Laptops, desktop monitors
xl:       1280px       Large widescreen displays
--------------------------------------------------------------------------------

Beginner Example — Stacking vs Horizontal Layout:
```tsx
<!-- On mobile: stacks vertically with flex-col
     On tablets and up (md:): arranges horizontally in a row -->
<div className="flex flex-col md:flex-row items-start md:items-center justify-between p-4 gap-4">
  <h2 className="text-lg font-bold">Tower A Progress</h2>
  <button className="w-full md:w-auto px-4 py-2 bg-blue-600 text-white rounded">
    Inspect
  </button>
</div>
```

3. DARK MODE ARCHITECTURE WITH CSS VARIABLES
================================================================================
Modern web applications support Dark Mode out of the box.

How Tailwind Handles Dark Mode:
1. Add `dark:` variant to your markup:
   ```tsx
   <div className="bg-white text-gray-900 dark:bg-gray-900 dark:text-gray-100">
     Content automatically adapts when the 'dark' class is present on <html>
   </div>
   ```

2. CSS Variable Theming (shadcn convention):
   Instead of hardcoding color hex codes, define semantic CSS tokens in `globals.css`:
   ```css
   :root {
     --background: 0 0% 100%;    /* Pure White */
     --foreground: 222 47% 11%;  /* Dark Navy */
     --primary: 221 83% 53%;     /* Bright Blue */
   }

   .dark {
     --background: 222 47% 11%;  /* Dark Slate */
     --foreground: 210 40% 98%;  /* Light Gray */
     --primary: 217 91% 60%;     /* Vibrant Blue */
   }
   ```
   This allows instant theme switching without modifying individual component files.

4. RADIX UI HEADLESS PRIMITIVES & THE SHADCN/UI REVOLUTION
================================================================================
Why Not Material UI (MUI) or Ant Design?
- Traditional component libraries install as huge locked packages in `node_modules`.
- Overriding their styling requires fighting complex CSS-in-JS abstractions.
- Adding custom accessibility or keyboard behavior is painful.

What is shadcn/ui?
shadcn/ui is NOT a library you install via `npm install shadcn-ui`.
It is a philosophy: **Copy-paste accessible components directly into your source code.**

The Three Layers of shadcn/ui:
1. **Radix UI (Functionality & Accessibility)**:
   Handles all complex behaviors: keyboard navigation (Arrow keys, Escape, Tab),
   focus traps, screen reader ARIA attributes, and portal rendering.
2. **Tailwind CSS (Appearance)**:
   Handles layout, borders, animations, and color theming.
3. **Your Codebase (Ownership)**:
   The files live in `components/ui/button.tsx` or `components/ui/dialog.tsx`.
   You have 100% control to modify every single line.

5. SONNER TOAST NOTIFICATIONS & MODERN USER FEEDBACK
================================================================================
Traditional web apps used `alert("Project Saved!")`, which blocks the browser thread
and looks outdated.

Sonner is the modern toast notification library adopted by enterprise Next.js teams:
- Unobtrusive, animated notification toasts that stack neatly in the corner.
- Completely customizable with Tailwind styling.

Usage in Next.js:
1. Add `<Toaster />` to your root `layout.tsx`:
   ```tsx
   import { Toaster } from 'sonner';

   export default function RootLayout({ children }) {
     return (
       <html>
         <body>
           {children}
           <Toaster richColors position="bottom-right" />
         </body>
       </html>
     );
   }
   ```

2. Trigger toasts from any Client Component:
   ```tsx
   import { toast } from 'sonner';

   function handleSave() {
     try {
       saveProject();
       toast.success('Project created successfully!');
     } catch (err) {
       toast.error('Failed to create project: ' + err.message);
     }
   }
   ```

6. BEGINNER PITFALLS & "INTERN WATCH-OUTS"
================================================================================
1. **Arbitrary Pixel Values Everywhere**:
   - Pitfall: Writing `w-[342px] mt-[13px] text-[15px]` defeats Tailwind's design system.
   - Fix: Stick to the standard scale (`w-80`, `mt-3`, `text-base`). Use arbitrary
     brackets `[ ]` only for rare, third-party embedded assets.

2. **Desktop-First Thinking**:
   - Pitfall: Writing styles expecting desktop first, then struggling to override for mobile.
   - Fix: Always resize your browser to 360px mobile view first. Style mobile, then
     add `md:` or `lg:` for wider screens.

3. **Mixing Conflicting Utility Classes**:
   - Pitfall: Writing `className="p-4 p-8"` causes unpredictable CSS cascade conflicts.
   - Fix: Use `tailwind-merge` (`twMerge`) or the `cn()` helper function included in shadcn.

7. MEMORY HACKS & SUMMARY CHEAT SHEET
================================================================================
- **The Box Model in Tailwind**:
  - `p-` = Padding (inside the border)
  - `m-` = Margin (outside the border)
  - `border` = Border line
  - `rounded-` = Border radius (rounded corners)

- **Flexbox Positioning**:
  - `flex justify-between` = Space between items
  - `flex items-center` = Center vertically
  - `flex flex-col md:flex-row` = Stack on mobile, row on tablet/desktop

- **shadcn Formula**:
  `Radix UI (Headless Accessibility) + Tailwind CSS (Utility Styling) = Full Ownership`
