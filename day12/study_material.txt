1. THE MENTAL MODEL: WHY DTOS AND VALIDATION PIPES MATTER?
================================================================================
When building backend APIs, NEVER trust data received from the client.
A client might send:
- Strings where numbers are expected (`"towerCount": "five"`).
- Empty strings or missing required fields (`"name": ""`).
- Out-of-bounds values (`"towerCount": -9999`).
- Injected unauthorized fields (`"role": "SUPERADMIN"`, `"isAdmin": true`).

If you don't validate at the entry point:
- Your database will throw cryptic SQL constraint errors.
- Your application could crash with uncaught `TypeError`s.
- Attackers can exploit Mass-Assignment vulnerabilities to elevate their permissions.

What is a DTO (Data Transfer Object)?
A DTO is a TypeScript class that defines the exact shape and validation contract
for incoming network requests.
- DTO = What the client is ALLOWED to send.
- Entity = How the data is stored in the database.

2. DECLARATIVE VALIDATION WITH CLASS-VALIDATOR
================================================================================
Instead of writing 50 repetitive `if (!req.body.name || req.body.name.length < 3)` 
statements, NestJS uses declarative decorators from `class-validator`:

Common Decorators:
--------------------------------------------------------------------------------
Decorator              Example Usage                 Validation Rule
---------------------  ----------------------------  ---------------------------
@IsString()            @IsString()                   Must be a primitive string
@IsNotEmpty()          @IsNotEmpty()                 Cannot be empty string/null
@MinLength(n)          @MinLength(3)                 Minimum length of 3 chars
@MaxLength(n)          @MaxLength(100)               Maximum length of 100 chars
@IsInt()               @IsInt()                      Must be an integer number
@Min(n) / @Max(n)      @Min(1) @Max(50)              Numeric value within bounds
@IsEnum(EnumType)      @IsEnum(ProjectStatus)        Must match one of the enum values
@IsOptional()          @IsOptional()                 Field is optional (ignored if null)
@Transform()           @Transform(({value}) => ...) Mutate/sanitize input (e.g. trim)
--------------------------------------------------------------------------------

Code Example:
```typescript
import { IsString, MinLength, MaxLength, IsEnum, IsInt, Min, Max, IsOptional } from 'class-validator';
import { Transform } from 'class-transformer';

export enum ProjectStatus {
  PLANNING = 'PLANNING',
  ACTIVE = 'ACTIVE',
  COMPLETED = 'COMPLETED',
  ON_HOLD = 'ON_HOLD'
}

export class CreateProjectDto {
  @IsString({ message: 'Project name must be a string' })
  @Transform(({ value }) => typeof value === 'string' ? value.trim() : value)
  @MinLength(3, { message: 'Project name must be at least 3 characters' })
  @MaxLength(100)
  name: string;

  @IsOptional()
  @IsString()
  @MaxLength(500)
  description?: string;

  @IsEnum(ProjectStatus, {
    message: 'status must be one of: PLANNING, ACTIVE, COMPLETED, ON_HOLD'
  })
  status: ProjectStatus;

  @IsInt({ message: 'Tower count must be an integer' })
  @Min(1, { message: 'Tower count must be at least 1' })
  @Max(50, { message: 'Tower count cannot exceed 50' })
  towerCount: number;
}
```

3. MASS ASSIGNMENT PROTECTION (VALIDATION PIPE)
================================================================================
In `main.ts`, we register `ValidationPipe` globally with enterprise security flags:

```typescript
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,            // Strips out any property without a DTO decorator
    forbidNonWhitelisted: true, // Throws 400 Bad Request if extra fields are passed!
    transform: true             // Automatically transforms request body into DTO class instance
  })
);
```

Security Impact:
If an attacker sends extra payload fields like:
```json
{
  "name": "Tower A",
  "status": "ACTIVE",
  "towerCount": 3,
  "role": "SUPERADMIN",
  "isAdmin": true
}
```
ValidationPipe immediately blocks the request before it reaches any service, 
returning HTTP 400 Bad Request:
```json
{
  "statusCode": 400,
  "message": [
    "property role should not exist",
    "property isAdmin should not exist"
  ],
  "error": "Bad Request"
}
```

4. NESTED DTO VALIDATION WITH @ValidateNested() & @Type()
================================================================================
In complex construction applications, a Tower contains an array of Floors.
To validate child objects inside an array:
1. You must use `@ValidateNested({ each: true })` from `class-validator`.
2. You MUST use `@Type(() => FloorDto)` from `class-transformer` so NestJS knows 
   which class to instantiate and validate.

Code Example:
```typescript
import { IsInt, Min, IsEnum, IsString, IsArray, ValidateNested } from 'class-validator';
import { Type } from 'class-transformer';

export class FloorDto {
  @IsInt()
  @Min(1)
  floorNumber: number;

  @IsEnum(['NOT_STARTED', 'IN_PROGRESS', 'COMPLETED'])
  status: string;
}

export class TowerDto {
  @IsString()
  name: string;

  @IsArray()
  @ValidateNested({ each: true }) // <-- Validates each item in the array
  @Type(() => FloorDto)           // <-- Tells transformer how to reconstruct FloorDto
  floors: FloorDto[];
}
```

5. ERROR ARCHITECTURE: CUSTOM APPEXCEPTION & GLOBAL FILTER
================================================================================
In large production systems, API clients need a consistent error JSON format across
all endpoints.

A. Custom `AppException`:
```typescript
export class AppException extends HttpException {
  constructor(message: string, statusCode = HttpStatus.BAD_REQUEST, errorName = 'AppException') {
    super({ statusCode, message, error: errorName }, statusCode);
  }
}

export class ProjectNotFoundException extends AppException {
  constructor(id: string) {
    super(`Project with ID ${id} was not found`, HttpStatus.NOT_FOUND, 'NotFoundException');
  }
}
```

B. Global `AllExceptionsFilter`:
Catches every uncaught exception and standardizes the response to exactly 5 fields:
```json
{
  "statusCode": 404,
  "message": "Project with ID proj-999 was not found",
  "error": "NotFoundException",
  "timestamp": "2026-10-14T02:00:00.000Z",
  "path": "/projects/proj-999"
}
```

6. BEGINNER PITFALLS & "INTERN WATCH-OUTS"
================================================================================
1. **Forgetting `@Type()` on Nested DTOs**:
   - Pitfall: Using `@ValidateNested()` without `@Type(() => ChildDto)` skips child 
     validation entirely because JavaScript does not retain runtime types.
   - Fix: Always pair `@ValidateNested()` with `@Type(() => ChildDto)`.

2. **Expecting Strings to Auto-Convert to Numbers Without `transform: true`**:
   - Pitfall: Passing `towerCount: "5"` in URL queries fails `@IsInt()` unless
     `transform: true` is configured in `ValidationPipe`.
   - Fix: Always enable `transform: true` in your global ValidationPipe.

3. **Not Catching Unwhitelisted Fields**:
   - Pitfall: Setting only `whitelist: true` strips extra properties silently without 
     alerting API consumers.
   - Fix: Use `forbidNonWhitelisted: true` so the API client is explicitly informed
     which field is invalid.

7. MEMORY HACKS & SUMMARY CHEAT SHEET
================================================================================
- **The Twin Decorators Rule**:
  `@ValidateNested({ each: true })` + `@Type(() => ChildDto)` must ALWAYS be used together!

- **Validation Pipe Trinity**:
  - `whitelist: true` (strips untracked fields)
  - `forbidNonWhitelisted: true` (blocks unexpected fields)
  - `transform: true` (instantiates real class instances)

- **Standard Error Schema (S-M-E-T-P)**:
  **S**tatusCode, **M**essage, **E**rror, **T**imestamp, **P**ath.
