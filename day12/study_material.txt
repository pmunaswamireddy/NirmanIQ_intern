1. WHAT IS A DTO (DATA TRANSFER OBJECT)?
--------------------------------------------------------------------------------
A Data Transfer Object (DTO) is an object that defines how data is sent over
the network between the client and the backend server.

Why use DTOs?
- Enforce strict input contracts before any business logic runs.
- Prevent mass-assignment security vulnerabilities (e.g., users injecting
  `isAdmin: true` into a profile update request).
- Separate presentation-layer validation from database entity models.
- Self-documenting endpoints for API consumers and OpenAPI/Swagger.

Comparison:
- Python FastAPI / Pydantic: `class CreateProject(BaseModel): name: str`
- NestJS: TypeScript class decorated with `class-validator` decorators.


2. CLASS-VALIDATOR & CLASS-TRANSFORMER
--------------------------------------------------------------------------------
In NestJS, input validation is declarative using annotations from `class-validator`.

Common decorators:
- `@IsString()`, `@IsNotEmpty()`, `@MinLength(min)`, `@MaxLength(max)`
- `@IsInt()`, `@Min(val)`, `@Max(val)`
- `@IsEnum(EnumType, { message: '...' })`
- `@IsOptional()` — allows null or undefined, but validates if provided
- `@Transform(({ value }) => ...)` from `class-transformer` — mutate input (e.g. trim whitespace)
- `@ValidateNested({ each: true })` + `@Type(() => ChildDto)` — validate nested objects/arrays

Example:
```typescript
import { IsString, MinLength, MaxLength, IsEnum, IsInt, Min, Max } from 'class-validator';
import { Transform } from 'class-transformer';

export enum ProjectStatus {
  PLANNING = 'PLANNING',
  ACTIVE = 'ACTIVE',
  COMPLETED = 'COMPLETED',
  ON_HOLD = 'ON_HOLD'
}

export class CreateProjectDto {
  @IsString()
  @Transform(({ value }) => typeof value === 'string' ? value.trim() : value)
  @MinLength(3)
  @MaxLength(100)
  name: string;

  @IsEnum(ProjectStatus)
  status: ProjectStatus;

  @IsInt()
  @Min(1)
  @Max(50)
  towerCount: number;
}
```


3. VALIDATION PIPE & MASS ASSIGNMENT PROTECTION
--------------------------------------------------------------------------------
NestJS ships with a built-in `ValidationPipe`. When configured globally in `main.ts`:

```typescript
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,              // Strips out any property not defined in the DTO
    forbidNonWhitelisted: true,   // Throws 400 Bad Request if extra properties are sent
    transform: true               // Automatically converts plain payloads into DTO instances
  })
);
```

Security Impact:
If a malicious client sends:
```json
{
  "name": "Tower A",
  "status": "ACTIVE",
  "towerCount": 4,
  "role": "SUPERADMIN"
}
```
ValidationPipe immediately rejects it with:
```json
{
  "statusCode": 400,
  "message": ["property role should not exist"],
  "error": "Bad Request"
}
```


4. NESTED VALIDATION WITH @ValidateNested() & @Type()
--------------------------------------------------------------------------------
When a payload contains child objects or arrays of child objects (e.g., a Tower
containing an array of Floors), `class-validator` requires both `@ValidateNested()`
and `class-transformer`'s `@Type()`:

```typescript
export class FloorDto {
  @IsInt()
  @Min(1)
  floorNumber: number;

  @IsEnum(['NOT_STARTED', 'IN_PROGRESS', 'COMPLETED'])
  status: string;
}

export class TowerDto {
  @IsString()
  @MinLength(2)
  name: string;

  @IsArray()
  @ValidateNested({ each: true })
  @Type(() => FloorDto)
  floors: FloorDto[];
}
```


5. CUSTOM EXCEPTIONS & GLOBAL EXCEPTION FILTERS
--------------------------------------------------------------------------------
NestJS provides built-in HTTP exceptions:
- `HttpException` (base)
- `BadRequestException` (400)
- `UnauthorizedException` (401)
- `NotFoundException` (404)
- `ForbiddenException` (403)

Enterprise Best Practice:
Extend `HttpException` to create domain-specific exceptions, and register an
`ExceptionFilter` globally to standardize all error responses:

```typescript
export class AppException extends HttpException {
  constructor(message: string, statusCode = HttpStatus.BAD_REQUEST, errorName = 'AppException') {
    super({ statusCode, message, error: errorName }, statusCode);
  }
}

export class ProjectNotFoundException extends AppException {
  constructor(id: string) {
    super(`Project with ID ${id} was not found`, HttpStatus.NOT_FOUND, 'NotFoundException');
  }
}
```

Global Filter Response Format:
```json
{
  "statusCode": 404,
  "message": "Project with ID proj-999 was not found",
  "error": "NotFoundException",
  "timestamp": "2026-10-14T02:00:00.000Z",
  "path": "/projects/proj-999"
}
```
